🛠 第2層：実施済みセキュリティ対策

🔑

APIキーの一元管理・分離

✓ 実施済み

Notion・Claude API・LINE Messaging APIのトークンが各プロジェクトフォルダの .envファイルに分散・平文保存されていた状態を改善。 共通APIキーを単一の安全な場所に集約しました。

実施内容
  • ホームディレクトリ直下に .secrets/.env を作成し、共通キーを集約
  • 各プロジェクトの .env はDB IDなどプロジェクト固有値のみに限定
  • Pythonスクリプト3本・Node.jsサーバーのenv読み込み処理を更新（共通→プロジェクト固有の優先順位）
  • .secrets フォルダをWindowsの隠しフォルダに設定
効果
  • プロジェクトフォルダを第三者と共有・コピーしてもAPIキーが漏洩しない
  • キーの棚卸し・ローテーションが1か所で完結する
🔒

シークレットファイルのアクセス権限制限

✓ 実施済み

.secrets フォルダのWindowsアクセス権限を自分のユーザーアカウントのみに制限。 他のユーザーアカウントや一般的なプロセスからの読み取りを防止します。

実施内容
  • icacls コマンドで fkdka ユーザーのみフルコントロールに設定
  • attrib +h で隠し属性を付与（エクスプローラーから見えない）
🔐

ダッシュボードへのBasic認証追加

✓ 実施済み

localhost:3456 で動作するダッシュボードが認証なしで操作できた問題を修正。 ブラウザの標準的なBasic認証ダイアログで保護します。

実施内容
  • server.js に checkAuth() 関数を実装
  • 認証情報は .secrets/.env の DASHBOARD_USER / DASHBOARD_PASS で管理
  • 認証失敗時は 401 Unauthorized を返し、ブラウザが認証ダイアログを表示
  • OPTIONSリクエスト（CORSプリフライト）は認証スキップ（仕様上の必要性）
効果
  • 同一LAN内の他端末からダッシュボードを操作されるリスクを防止
  • ツールの起動・停止・設定変更を認証者のみに限定
🌐

CORSポリシーをlocalhostのみに制限

✓ 実施済み

APIサーバーが Access-Control-Allow-Origin: *（全オリジン許可）で動作していた問題を修正。 悪意あるウェブサイトがユーザーのブラウザ経由でAPIを呼び出せる状態（CSRF的リスク）を解消します。

変更内容
項目 変更前 変更後
許可オリジン * （すべて許可） localhost / 127.0.0.1 のみ
file:// ページ 許可 引き続き許可（null オリジン対応）
外部ドメイン 許可 ブロック
🔌

サーバーを127.0.0.1にバインド（外部アクセス完全遮断）

✓ 実施済み

Node.jsサーバーがデフォルト（0.0.0.0）で起動していたため、 同一LAN内の端末から直接アクセス可能な状態でした。 127.0.0.1 にバインドすることでOSレベルで外部アクセスを遮断します。

実施内容
  • server.listen(PORT) → server.listen(PORT, '127.0.0.1') に変更
  • 管理者権限不要・OS設定変更なしで即時有効
  • ファイアウォールより確実（Windowsファイアウォールは設定が上書きされる可能性がある）
効果
  • カフェや公共Wi-Fiでも外部からのアクセスが物理的に不可能
  • Basic認証との2段構えで、より堅牢な防御を実現
📝

server.js内のハードコードトークンを環境変数化

✓ 実施済み

🤖 第1層：Claude Codeセキュリティ設定

Claude Codeはターミナル経由でPC内のファイルを直接操作できる強力なAIツール。 チャット型AIとは異なり、設定なしで使い続けることはファイル削除・データ漏洩などのリスクを自分で引き受けることになる。 以下は実際に settings.local.json と CLAUDE.md に追加したセキュリティ設定の記録。

# 設定内容 設定方法 状態
1 サンドボックス有効化（作業フォルダ外に出たら確認） sandbox.enabled ✓ 完了
2 サンドボックスの抜け道を塞ぐ allowUnsandboxedCommands: false ✓ 完了
3 危険コマンドを拒否リストでブロック permissions.deny ✓ 完了
4 .envファイルの読み取りをブロック permissions.deny ✓ 完了
5 ネット接続先を許可ドメインのみに制限 sandbox.network.allowedDomains ✓ 完了
6 CLAUDE.mdにリスク表示ルールを追記 CLAUDE.md ✓ 完了
7 月1回の権限棚卸し（/permissions） 運用習慣 △ 運用で対応
📦

設定1：サンドボックス有効化

✓ 実施済み

Claude Codeがパソコン全体を自由に操作できる状態から、作業フォルダ内だけに範囲を絞る仕組み。 確認画面の連打（証人疲れ）を防ぎ、本当に注意が必要な操作だけ確認が出るようになる。

settings.local.json に追加した設定
  • "sandbox": { "enabled": true } でサンドボックスを有効化
  • "autoAllowBashIfSandboxed": true で作業フォルダ内は確認なしで自動許可
効果
  • Anthropic社内テストでは確認画面が84%減少
  • フォルダ外に出ようとした時だけ確認が出るため見落としがなくなる
🚧

設定2：サンドボックスの抜け道を塞ぐ

✓ 実施済み

設定1のサンドボックスには「ここでは動かないのでフォルダの外に出ます」と Claude Codeが自ら申告して外に出られる抜け道がある。 allowUnsandboxedCommands: false でその選択肢自体をなくす。

settings.local.json に追加した設定
  • "allowUnsandboxedCommands": false
  • 確認画面すら出ずに問答無用でブロック
設定1との関係
  • 設定1 = 作業フォルダに囲いを作る
  • 設定2 = その囲いから出られないようにする
  • 2つセットで初めて完成する設定
🚫

設定3：危険コマンドの拒否リスト

✓ 実施済み

どれだけYesを連打しても、拒否リストのコマンドは絶対に実行されない。 エンジニアでなくても「AIが勝手に判断して実行したら致命的なもの」を5種類厳選してブロック。

ブロック対象コマンド（permissions.deny に追加）
  • rm -rf * / rm -r * — ファイルの再帰的削除
  • sudo * — 管理者権限への昇格
  • chmod * / chown * — ファイル権限・所有者の変更
  • dd * — ディスクレベルの直接書き込み
  • git push --force* / git push -f * — 強制プッシュ
サンドボックスとの使い分け
  • サンドボックス = どこで作業するかの制限（場所）
  • 拒否リスト = 何をやらせないかの制限（行動）
  • 場所と行動の両面からガードをかける
🔑

設定4：.envファイルの読み取りブロック

✓ 実施済み

Claude Codeが読み込む外部コードに「.envの中身を外部サーバーに送れ」という命令が こっそり仕込まれていた場合（プロンプトインジェクション攻撃）、 .envファイル自体を読めないようにすることでパスワード・APIキーの漏洩を防ぐ。

permissions.deny に追加したルール
  • Read(**/.env) — .env ファイルの読み取りを禁止
  • Read(**/.env.*) — .env.local / .env.production 等も同様に禁止
なぜ必要か
  • Claude Code自体が悪さをするわけではない
  • 外部から読み込んだコードに悪意ある命令が仕込まれるリスクへの対策
  • 読み込み自体を禁止すれば攻撃が成立しない
🌐

設定5：ネット接続先を許可ドメインのみに制限

✓ 実施済み

設定4でパスワードファイルを読めなくした上で、さらに仮に読まれてもデータの送り先自体をブロックする二重の守り。 許可ドメインへの通信は確認なしで通り、それ以外は確認が出るようになる。

sandbox.network.allowedDomains に登録したドメイン
  • github.com / api.github.com — ソースコード管理
  • raw.githubusercontent.com — GitHub Rawファイル取得
  • api.anthropic.com — Claude API
  • pypi.org / files.pythonhosted.org — Pythonパッケージ
  • npmjs.org / registry.npmjs.org — npmパッケージ
  • yarnpkg.com — Yarnパッケージ
  • www.lancers.jp — 業務利用サイト
📋

設定6：CLAUDE.mdにリスク表示ルールを追記

✓ 実施済み

Claude Codeは作業開始時に毎回CLAUDE.mdを読む。ここに「操作前にリスクを数字で示し、 日本語で何をしようとしているか説明してから確認を求めること」というルールを書いておく。 「ただ実行していいですか」と聞かれるのとは判断のしやすさがまるで違う。

CLAUDE.md に追加したルール（概要）
  • 取り返しのつく可能性がある操作の前に日本語で内容を説明
  • データ漏洩リスク・ファイル削除リスク・外部送信リスクをパーセントで提示
  • 確認後に実行する
1〜5との組み合わせ
  • 設定1〜5 = 物理的にブロックする「壁」
  • 設定6 = Claude Code自身の判断力を底上げする「知恵」
  • リストに入れ忘れた操作や想定外のパターンへの最後の砦
🗓

設定7：月1回の権限棚卸し

△ 運用で対応

設定1〜6で作った守りの上から、使い続けることで「今後も許可」がどんどん積み上がっていく。 月1回 /permissions コマンドで現在の権限一覧を確認し、 意図せず許可されたルールがあれば削除する習慣をつける。

実施方法
  • Claude Codeで /permissions と入力
  • 表示された一覧の中に「許可した覚えのないもの」がないか確認
  • 不要なものはその場で削除できる
補足
  • 設定ファイルの正体は settings.local.json の1ファイルだけ
  • 全リセットしたい場合はこのファイルを削除するだけで元通り
  • 大事なデータを扱う時だけ設定を入れる使い分けも可能
